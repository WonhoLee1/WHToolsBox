# doe UI

- config 변수 dict key 값으로 접근하여 정의할 수 있으면 좋겠다.
- 이산형 값을 list로 정의할 수도 있고, start:end:numbers로 정의할 수도 있다.
  [10,30,100], [10:100:4]  
- 연속형 min:max:init
   10:30:15
- doe 적용시 기본 설정은 latin hyper cube, full fact, monte carlo 100
    다른 sampling 방법 지원 가능한 것이 있으면 나열 해주세요.
    이상형과 연속형이 썩여있는 경우도 가능해야 하구요.

-base가 되는 config를 인자로 받았고, doe sampling을 통하여 각 라인에 대한 config를 생성하고 어떤 인자가 어떻게 변경되었는지를 기록하여 list of dict로 반환하겠다.
즉,
doe case number, varname1, varname2, varname3, ...  를 열제목으로 하는 데이터의 형식으로 반환하다.
이게 dict로 key를 열제목으로 하고, value를 각각의 값으로 하는 dict로 구성된 list가 반환되어도 좋고 ...
그리고 거기에 해당하는 config도 변경 적용되어 반환될 수 있다.

- `config['a']['bbb']` 와 같은 접근도 기술할 수 있다.

- 범용의 방법으로 정의하는 것이라 텍스트로 나열하는 방법을 채택하겠다.

cfg['a']['b'] = [10,20,30]
cfg['a']['f'] = [10:199:15]
cfg['d'] = 10:200:100
정규분포 기준 중심값과 산포를 부여하는 방법도 제공하자. 어떻게 입력을 하게 하면 좋을까?   norm:mean:std:number -> number를 입력하지 않는 경우도 가능하다. (full fact이 아닌 경우)
정규분포 형식으로 입력하는 경우, latin hyper cube 방식이나 monte carlo 방식을 사용해서 정한 수량의 sample을 생성할 수 있고 seed를 정할 수도 있다.

문자열도 사용할 수 있는데, 이 때는 연속형은 안되겠지?

어떤 값이 있는지를 모르니까, 이 목록을 보여주는 선택을 할 수 있는 tree형 테이블이 Add Variable을 클릭하면 나타나서 선택할 수 있도록 한다.

입력한 형식이 허용 가능한 것인지 검사하는 기능을 제공한다.

make doe list 버튼을 누르면 doe list table을 보여준다.
직접 doe list table에서 내용을 수정할 수 있으며, 변경된 내용을 적용할지 물어보고 OK면 적용한다.
그리고 최종 OK를 누르면 이 UI dialog를 호출한 곳에 반환한다.

이것은 WHToolsBox 하위 폴더 모듈로 만들자. 다른 프로그램에서도 사용할 수 있는 모듈이기를 원한다.

# TVPackageMotionSim에서의 사용

Control UI에서도 doe를 정의할 수 있고, 코드로도 정의할 수 있다.
그래서, code로 정의하고 사용하는 방법을 먼저 고안하자.

doe 정의는 문자열로 규약으로 정의한다.
아래와 같은 방식이다.
'''
cfg['a']['b'] = [10,20,30]
cfg['a']['f'] = [10:199:15]
cfg['d'] = 10:200:100
'''

doe definition class에 생성자에 이 문자열과 config (dict기반)를 제시한다.
문법 체크 기능을 호출하면 성공, 실퍠의 여부와 문제가 있는 부분을 알려주는 메시지를 반환한다.
doe 생성 함수를 호출하면 doe table와 config dict list를 반환한다.
만약 doe table을 수정해서 재생성 함수의 인자로 넣으면 다시 생성하여 반환한다. 다만, 이때는 doe table은 수정된 내용을 그대로 쓴다.

이 내용을 입력받고 doe 작업을 생성하고 실행하는 엔진을 TVPackageMotionSim 내에서 구현한다.
현재 run_parameter_stuy가 있는데 여기서 이 역할을 할 수 있을지 판단하라.

doe의 실행은 n개의 프로세스로 병렬 실행할 수 있게 지원한다. 각각의 프로세스는 독립적으로 배치로 실행된다.
실행 상황을 모니터 할 수 있는 text 형식의 파일을 생성해준다.
결과 부모 폴더 내에 run_doe_log.txt파일이 생성되는 것이다.
이 파일은 append 구조가 아니라 매번 새롭게 리라이트된다.

n개의 작업의 수에 맞게 현재 4열의 박스로 n개 작업에 맞게 행으로 구성한다.
process id, target_time, current_time, frame 이 표시된다.

완료가 되면 run_doe_log.txt에서는 나타나지 않게 되고 다른 run 작업으로 대체된다.
박스의 위치를 정해지면 변동을 하지 않는다.

done_doe_log.txt에 해당 박스와 내용이 행열 위치없이 append 되는 방식으로 남긴다.

결과 파일은 기존 단일 작업 출력 내용과 동일하다. 다만, results에 위치하지 않고 doe definition class 생성 시에 또는 멤버 함수로 폴더 위치를 정할 수 있다.
기본은 results 폴더이며, DOE_D{날짜}_{시간}으로 구성한다.
DOE 진행 시의 카메라 각도를 입력할 수 있고, 그 뷰를 기준으로 정해진 해상도로 mp4를 캡쳐하여 결과 폴더에 저장하는 기능을 제공한다.

# 낙하 시점 추출 알고리즘의 구현

- 개요: 코너가 지면에 닿는 시점을 알아내어 닿기 직전의 상태의 시간/프레임을 알려주는 기능
- 고민사항
 . 코너가 지면에 닿는게 애매하거나 통통 튀는 현상이 있으면 어떻하지?
 . 각 코너가 이력 상 최초로 닿는 시점을 기준으로 결정하다.
 . 전체 해석 시간 동안 각 코너를 모두 검색한다.
 . 지면에 닿는 순서대로 연속된 문자열로 낙하자세를 설명한다. ContactSeqStr 라고 하겠다.
 . 예) C4-C3-C2-C1
 . ContactSeqStr에 해당하는 각 코너에 대해서 ContactSeqTime이 저장되는 ContactSeqTimeList가 있다. [ ['C4', 10.1], ... ] 과 같이 구성된다. 코너명과 값이 Seq 순서와 동일하게 저장된다.
 . 시간은 접촉 바로 전 Frame에 해당하는 시간이다.
 . 이 기능은 현재 구현된 py 파일이 아닌 새로운 파일로 구현해달라. 다른 PC의 브랜치에 이식하기 좋게 한다.
 . result 인스턴스를 받으면 이 계산을 해주는거지.
- 추가 아이디어
 . 접촉 전 시점, 접촉 후 시점을 알고 있으니 그 주변에서 코너 접촉력이 최대가 되는 값을 기록하자. ContactSeqForce가 되겠네.
 . ContactSeqForceList로 저장하면 되겠구나. [ ['C4', 10.1], ...]
 . 이러고 보니 ContactSeqTimeList와 ContactSeqForceList는 1:1로 대응되는 리스트가 되겠구나. 그러면 좀 더 dict로 구조적으로 다룰 수도 있겠는데? 아이디어로 제공해달라.
 . 접촉이 유지되는 시간까지 확인해서 전체 시간에 대해서 코너별 접촉력*시간에 해당되는 에너지? 같은 값을 기록하자. ContactSeqImpactList로 저장하면 되겠구나. [ ['C4', 10.1], ...]
 . 이 세개를 한 번에 기록하는 ContactSeqList를 생성하는 함수로 만들면 되겠네.
- 이 알고리즘은 목표 시간까지 시뮬레이션 끝나고 결과 파일 저장 전에 호출되어서 result 인스턴스에 추가로 데이터 처리 및 저장을 유도하고 pkl 파일이 저장되게 할 것 이다.
- 접촉 직전의 장면에서는 캡쳐를 하여 결과 폴더 내에 contacts 폴더를 만들고 (없다면, 있다면 그대로 사용) 캡쳐 그림을 저장한다.
