# OpenRadioss 모델 생성 시 프레임 자세 및 초기 속도 매핑 수정 계획 (2026-06-08)

## 1. 개요 및 문제 분석
- **현상**: GUI 상에서 슬라이더를 조작하여 과거 프레임을 렌더링하고 있을 때 `generate model` 또는 `Run engine`을 실행해도, 실제 생성된 OpenRadioss `.rad` 파일의 기하학적 자세와 초기 속도가 사용자가 보고 있는 시점의 상태와 일치하지 않음.
- **원인 분석**:
  1. **중복 메서드 정의 및 파라미터 누락**: `whts_control_panel.py` 파일 내에 `_on_create_radioss_model` 메서드가 두 번 중복 정의되어 있었음. 그 중 뒷부분에 선언된 메서드가 앞부분을 덮어쓰고 있었는데, 이 메서드는 `self.sim.export_radioss()`를 아무 파라미터 없이 호출하여 결과가 있을 경우 항상 최종 프레임(`frame_idx = -1`)으로 동작하도록 되어 있었음.
  2. **초기 속도 하드코딩**: `whts_radioss_builder.py`에서 초기 속도 카드를 쓸 때, 전달받은 3차원 선속도(`v_vec`)와 각속도(`omega_vec`)를 무시하고 오직 낙하 높이에 비례한 중력 낙하 초기 속도 `v0 = sqrt(2*g*h)` 값만 Z축 선속도로 하드코딩하여 반영하고 있었음.

## 2. 수정 계획
- **whts_control_panel.py**:
  - 중복 정의된 `_on_create_radioss_model` 메서드를 단일 정의로 통합.
  - 시뮬레이션 결과 데이터가 존재하는 상태에서 모델을 생성할 때, 현재 슬라이더가 멈춰 있는 프레임 인덱스(`self.slider.value()`)를 `export_radioss(frame_idx=frame_idx)` 형태로 넘겨주도록 변경.
  - 결과가 없는 실시간 런타임 상태에서는 기존처럼 실시간 물리 데이터를 사용하도록 폴백 구현.
- **whts_radioss_builder.py**:
  - `v_vec` (MuJoCo m/s 단위 -> mm/s 단위 변환 필요하므로 `* 1000.0` 적용) 및 `omega_vec` (rad/s) 값을 실제 `/INIVEL/TRA` (선속도) 및 `/INIVEL/ROT` (각속도) 카드로 기입하도록 개선.
  - 만약 두 속도 벡터의 크기가 거의 0일 때(예: 시뮬레이션 재생 시작 시점)는 기존의 중력 자유 낙하 기준 속도 `-v0`를 Z축 선속도로 설정하여 정상 작동 보장.

## 3. 검증 방법
- syntax 오류 컴파일 테스트 완료.
- 모델 생성 시 로그를 확인하여 현재 프레임 인덱스와 그에 매치하는 타겟 시간이 잘 전달되는지 검증.
