# 이산형 모델 용접부(Weld) 강성 제어 및 `torquescale` 적용 기술 문서

본 문서는 MuJoCo 기반 포장 낙하 시뮬레이션(TVPackageMotionSim)에서 섀시(Chassis), 오픈셀(Opencell), 완충재(Cushion) 등 주요 부품의 실제 굽힘/비틀림 고유진동수를 모사하기 위해 도입된 **용접부(Weld) 강성 제어 기법** 및 **`torquescale` 적용 내용**을 정리합니다.

---

## 1. 배경 및 필요성

MuJoCo의 이산형 블록(Discrete Block) 모델링 방식에서는 낱개 블록들을 서로 강한 스프링-댐퍼 시스템인 `<weld>`로 결합하여 하나의 플레이트(Plate) 거동을 모사합니다. 
* **축방향 강성(Axial Stiffness)**: 수치적 안정성을 위해 높은 강성을 유지해야 합니다 (Time step 내 최대 인장 강성 유지, 약 1000Hz 수준 capping).
* **굽힘/비틀림 강성(Bending/Torsional Stiffness)**: 실제 부품의 얇은 두께 대비 유연한 굽힘 및 비틀림 거동을 표현해야 합니다.
* **`torquescale` 도입**: 회전/비틀림(Torque) 방향의 스프링 강성을 선별적으로 감쇄시키는 MuJoCo의 `torquescale` 속성을 통해, 축 강성을 유지하면서도 실제 판재의 비틀림 고유진동수(Chassis 2.0Hz, Opencell 13.89Hz)에 완벽히 매칭하도록 유도합니다.

## 2. 기존 문제점 및 원인 분석

1. **`TypeError` 발생 (인자 누락)**
   * `whtb_base.py` 및 `whtb_builder.py`는 `get_weld_xml_strings(config)` 호출 시 `config`를 넘겨받도록 수정되었으나, 자식 클래스인 `BCushion`에서 오버라이드한 `get_weld_xml_strings` 시그니처가 `self`만 받고 있어 실행 시 `TypeError`가 발생하며 모델 빌드가 중단되었습니다.
2. **완충재 `torquescale` 주입 누락**
   * 완충재(`BCushion`) 내부의 용접 엘리먼트(`<weld>`) 생성 문자열에 `torquescale` 속성 자체가 누락되어 있어, 사용자가 설정한 `cushion` 및 `cushion_corner` 용접 강성 약화(예: `torquescale=0.1`)가 시뮬레이션에 무시된 채 MuJoCo 기본값인 `1.0`으로 고정되어 해석되었습니다.
3. **`KeyError: 'welds'`에 대한 예외 처리 미비**
   * `whtb_builder.py` 단독 기동 시처럼 `config` 내부에 `"welds"` 정의가 누락된 경우, `config["welds"]`와 같이 직접 인덱싱하여 불러오면서 프로그램이 죽는 에러가 발생했습니다.
4. **`use_weld=False` 세팅으로 인한 굽힘 거동 무력화**
   * `run_drop_simulation_cases_v6.py`의 `fast mode` 구성 시 `opencell` 및 `chassis` 컴포넌트의 `"use_weld"` 값이 `False`로 지정되어 있었습니다. 이 상태에서는 개별 블록들이 서로 연결되지 않고 단일 강체(Rigid body)로 구성되므로, `torquescale` 값을 아무리 작게 튜닝하더라도 비틀림 변형량이 `0.00`으로 고정되는 현상이 발생했습니다.

## 3. 구현 내용 및 해결 방안

### ① `whtb_models.py` 수정: `BCushion` 클래스 리팩토링
`BCushion` 클래스의 용접 생성 함수가 `config` 인자를 수용하여 `torquescale` 값을 XML에 주입하도록 수정했습니다.

```python
    def get_weld_xml_strings(self, config: Optional[Dict[str, Any]] = None) -> List[str]:
        weld_xml = []
        if not self.use_internal_weld:
            for child in self.children:
                weld_xml.extend(child.get_weld_xml_strings(config))
            return weld_xml
            
        # config에서 파트별 torquescale 조회 (기본값 1.0)
        ts = 1.0
        if config and "welds" in config:
            w_name = self.name.replace("B", "", 1) if self.name.startswith("B") else self.name
            w_name = w_name.lower()
            for k, v in config["welds"].items():
                if k.lower() == w_name:
                    ts = v.get("torquescale", 1.0)
                    break
        
        # ... (중략: 인접 블록 용접 탐색 루프)
                    if match:
                        is_c2 = self.is_corner_block(ni, nj, nk)
                        w_class = "weld_bcushion_corner" if (is_c1 or is_c2) else "weld_bcushion"
                        
                        site1_name = f"s_{self.name}_{i}_{j}_{k}_{suffix}"
                        opp_suffix = "NX" if suffix=="PX" else "NY" if suffix=="PY" else "NZ"
                        site2_name = f"s_{self.name}_{ni}_{nj}_{nk}_{opp_suffix}"
                        # [V6.2 PATCH] torquescale 속성 동적 주입 추가
                        weld_xml.append(f'        <weld class="{w_class}" site1="{site1_name}" site2="{site2_name}" torquescale="{ts:.6f}"/>')
                        
        for child in self.children:
            weld_xml.extend(child.get_weld_xml_strings(config))
        return weld_xml
```

### ② `whtb_builder.py` 수정: `KeyError` 방어 적용
`config`에 `"welds"` 키가 없을 경우에도 안전하게 작동할 수 있도록 `config.get("welds", {})` 형태로 호출 구조를 전면 개편했습니다.
* `w_prop = config.get("welds", {}).get("auxboxmass", {"torquescale": 1.0})`
* `w_prop = config.get("welds", {}).get(w_name, {"solref": [0.02, 1.0], "solimp": [0.1, 0.95, 0.005, 0.5, 2], "torquescale": 1.0})`

## 4. 적용 방법 및 검증 결과

1. **XML 파일 검사**:
   * 시뮬레이션 모델 생성 시 XML 파일 내부의 `<weld>` 엘리먼트에 각 컴포넌트(`opencell`, `chassis`, `cushion`)의 계산된 `torquescale` 값이 정상 기입됩니다:
     * **Chassis (2.0Hz 타겟)**: `torquescale="0.000072"` 적용 완료
     * **Opencell (13.89Hz 타겟)**: `torquescale="0.003472"` 적용 완료
     * **Cushion (뒤틀림 튜닝)**: `torquescale="0.001000"` 적용 완료
2. **거동 검증 및 가이드**:
   * 컴포넌트의 `"use_weld"` 속성을 `True`로 명시해야만 이산 용접 결합이 생성되어 `torquescale`에 의한 비틀림 유연성이 발현됩니다.
   * `use_weld: True` 상태에서 시뮬레이션을 수행한 결과, `bopencell`과 `bchassis` 모두에서 물리적 굽힘 모멘트에 의한 **Max Bend** 및 **Max Twist** 각도가 유효하게 계측됨을 확인했습니다.
